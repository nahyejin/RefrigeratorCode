## 4. 환경 점검 결과 (정직하게)

**되는 것**
- Android 에뮬레이터 `cookmatch_pixel`(WHPX, API 36): 부팅 16~40초(스냅숏), adb 연결, `rec_lib.forward()` 로 CDP(9222) 연결, `adb screenrecord` 1080x2400 녹화 → 크롭 940x1920·30fps 재인코딩 — 모두 정상.
- 앱은 **Capacitor 번들(앱 안에 들어 있는 dist)** 이라 개발 서버(5178)·로컬 백엔드(5000)와 연결되지 않는다. 데이터는 **운영 서버(Railway) 읽기(GET)** 만 쓴다. → UI 가 바뀔 때마다 앱을 다시 빌드해 설치해야 한다: `git worktree add --detach <경로> origin/main` → `frontend/node_modules` 를 다른 작업 폴더의 것으로 junction → `npx vite build` → `npx cap sync android` → `gradlew assembleDebug`(약 35초, JAVA_HOME=Android Studio jbr) → `adb install -r`. (이번엔 `061f320b` 로 빌드. 작업 폴더의 미커밋 변경은 안 섞임. 끝난 뒤 junction 먼저 지우고 worktree 제거.)

**막히던 곳 / 옛 녹화 스크립트가 새 UI 에서 깨지는 곳**
1. 대체 칩이 `span` 이 아니라 **`button`(배경 rgb(58,58,66), title 「A 대신 B 써도 되는지 쿡 코치에게 물어보기」)** — 누르면 레시피 창+쿡 코치가 열린다(옛 `isSub` 선택자 실패). 이번엔 이걸 **코치 장면의 시작**으로 씀.
2. 필터를 걸면 목록 위에 「최근 · 매칭 60~99% ✕ · 모두 지우기」 줄이 생겨 스크롤 위치 계산이 달라짐. 「최근」 칩은 `cookmatch_recent_recipe_conditions_v1` 에 남아 이전 검색이 보임 → 시드에서 지움.
3. 비회원 **로그인 확인창**: 「다시 와 주셨네요」(2번째 방문, `cookmatch_return_gate_at`)·「이 냉장고, 저장해 둘까요?」(첫 레시피 열람 뒤, `cookmatch_save_prompt_at`)가 녹화 중 뜬다 → 시드에서 미리 「방금 띄움」 표시.
4. 시드 재료 id 가 `seed-…` 형식이면 「직접 담은 재료」로 세어져 **3개 한도**에 걸림(`isSeedIngredientId` 는 `fridge-<ts>-<n>` 형식만 기본 재료로 봄) → `scripts/seed_fridge_v2.js`.
5. 「AI 식단」·「이번 주 AI 식단」 버튼은 없어짐(→ `/plan` 「식단 짜기」 한 화면, 칩 누르면 버튼이 「조건에 맞춰 짜기 · 3 크레딧」). 「요리 AI」는 「쿡 픽」(플로팅 버튼 `data-guide-target="chat-fab"`, 입력창 placeholder 「먹고 싶은 걸 편하게 말해보세요」는 그대로).
6. 채팅 창을 열면 **소프트 키보드**가 올라와 화면 절반을 덮음 → 녹화 동안만 에뮬레이터의 키보드(IME 2개)를 꺼 두고 끝나면 되살림(`adb shell ime disable/enable`).
7. 사진 선택은 **안드로이드 시스템 사진 선택기**(영어 「Photos/Albums」)가 열려 JS 로 못 누름 → adb 좌표 탭(사진 → Done)으로 누르고, 영상에서는 그 구간을 잘라 냄. CDP 파일 선택창 가로채기는 이 앱(Capacitor)에서 안 먹었음.
8. 긴 목록에서 `window.scrollTo`·`scrollIntoView` 가 **목록이 다시 그려지는 동안**에는 먹히지 않음 → 결과가 뜬 뒤 3.5초 기다렸다가 `scrollIntoView`.
9. 첫 진입·목록 첫 로딩 때 앱의 새 로딩 화면(재료가 앉는 마크)이 3~4초 나온다 — 장면 앞부분을 잘라 씀.
10. 앞 장면이 남긴 시스템 창(사진 선택기)이 다음 녹화를 가림 → 장면마다 시작에 앱을 맨 앞으로 불러 닫음(`am start`).

**AI 크레딧 보호(과거 실제 호출 사고 대응) — `rec_lib_v2.Guard`**
- CDP `Fetch` 로 모든 요청을 붙잡아 GET/HEAD/OPTIONS 는 통과, **그 밖은 전부 서버로 안 보내고 가짜 200** (AI 4곳은 장면용 가짜 응답, 나머지는 `{}`). 막은 요청은 `rec_f_<장면>.json` 의 `guard` 에 남김.
- 실측: 장면마다 쓰기 요청 9~20건이 막힘 — 대부분 **쿠팡 파트너스 로그 POST** 와 **앱 자체 방문 기록 `POST /api/events`**(이게 그대로 나갔다면 운영 DB 에 비회원 이벤트가 쌓였을 것). AI 장면은 가짜 응답 1건씩(`/api/chat`·`/api/plan/suggest`·`/api/recipes/<id>/ask`·`/api/ingredients/recognize`). **실제 AI 호출 0, 운영 DB 쓰기 0**(preflight OPTIONS 는 통과 — 읽기와 같음).
