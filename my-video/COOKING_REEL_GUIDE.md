# 요리 릴스 만드는 법 (쿡매치) — 다음 대화에서도 이 파일부터 읽기

사용자가 직접 요리한 영상으로 인스타 릴스를 만든다. 1편: 소세지야채볶음(2026-10-15, `src/CookingSausage.tsx`).
새 편은 이 파일의 순서·규칙을 그대로 따르고, `CookingSausage.tsx` 를 복사해 장면 목록만 바꾼다.

## 0. 컨셉 정하는 법 (2026-10-16 사용자와 정함)

- **컨셉을 미리 정하지 않는다.** 사용자는 실제로 그날 만든 요리·실제 상황을 그대로 찍어 올린다(지어낸 상황 X — 1편이 좋았던 건 하원길 「소시지!」·양파뿐이었던 실제 이야기 덕분).
- 사용자가 할 일은 둘: ① 평소처럼 요리하며 찍기(그날의 짧은 이야기 장면 — 아이 대화·장보기·냉장고 열기 — 있으면 같이) ② 그 요리를 쿡매치에서 찾아 완료하는 과정 녹화(평소 쓰듯이, 방해 금지 모드 켜고).
- **강조할 기능은 Claude 가 편집 때 고른다** — 영상·앱 녹화에서 실제로 일어난 일 중 가장 잘 맞는 것 하나:
  | 영상에 이런 게 있으면 | 강조할 기능 | 이 편 CTA 슬로건(원래 릴스 `payoffLine`) |
  |---|---|---|
  | 없는 재료를 다른 걸로 대신(대체 칩) | 레시피 매칭 · 대체 재료 | 없는 재료 대신, 있는 걸로 바꿔드려요 (Reel2) |
  | 곧 상하는 재료를 씀 / 유통기한 알림 | 유통기한 알림 | 버리기 전에, 있는 재료부터 요리하세요 (Reel5) |
  | 장 보고 와서 영수증·사진으로 등록 | AI 재료인식 | 냉장고, 기억 안 해도 돼요 (Reel1) |
  | 이번 주 식단·장보기를 앱으로 짬 | AI 식단 | 이제 장보기도, 가장 효율적으로 (Reel4) |
  | 손이 바빠 읽어 주기로 들음 | 읽어주기 모드 | 레시피는 귀로 들으세요 (Reel3) |
  | 챗봇에 말로 물어봄 | 요리 AI | 검색 대신, 말 한마디면 충분해요 (Reel6) |
  | 인기순·유명 레시피·원문 영상 | 검증된 레시피 | 뭘 골라도 맛집이에요 (Reel7) |
  | 가족 캘린더·집밥 목표·아낀 돈 | 가족이 아낀 돈 | 가족과 함께 확인해요 (Reel8) |
  | 딱히 걸리는 게 없으면 | 내 냉장고 재료 매칭률(%) — 어떤 요리에도 있음 | 레시피 매칭(Reel2) |
- 같은 기능이 직전 편과 겹치면 영상에 있는 다른 기능으로 돌린다. 편별로 고른 기능을 아래 「회차 기록」에 적는다.

## 0-1. 후킹 자막 = 썸네일 (모든 편 통일, 2026-10-17 사용자 요청)

- **모든 편 첫 장면 가운데에 큰 노란 후킹 자막**을 넣는다 — 의외성·궁금증을 주는 한 문장(예: 2편 「황태로도
미역국을 끓인다고?」). 사용자가 이 장면을 **인스타 썸네일(커버)**로 쓴다 → 프로필 격자에서 편마다 같은 모양으로 보이게.
- 모양(2편 `CookingMiyeok.tsx` 의 `Hook` 그대로 재사용): 화면 가운데 위(top ≈ 640), 글자 118px·굵게(900)·노랑 `YELLOW`(#FFD600)·줄간격 1.18, 검은 그림자 `0 6px 22px rgba(0,0,0,0.8), 0 0 6px rgba(0,0,0,0.8)`, 2줄(앞 짧게 / 뒤 길게), 약 2.8초.
- **첫 프레임부터 꽉 보이게**(페이드·커지는 효과 없이 시작, 사라질 때만 페이드) — 썸네일을 첫 프레임에서 고를 때 글자가 흐리지 않게.
- 문구 고르는 법: 그 편 이야기에서 **「어? 그게 돼?」** 싶은 지점을 질문형으로. 사실과 다르게 과장하지 않는다(실제 상황에서 나온 말). 정답은 영상 안에서 풀린다.
- 1편(소세지야채볶음)은 이 규칙 전에 만들어 후킹 자막이 없다.

## 0-2. 후킹 문구 만드는 법 — 26가지 후킹 전략 (2026-10-17 사용자가 준 자료, 우리 상황에 맞게)

원래 자료는 「조회수 100만 릴스 전략가」용 브랜드 위주 프롬프트다. 우리는 **엄마가 실제로 해 먹인 집밥 이야기 + 쿡매치**라서 아래처럼 고쳐 쓴다.

### 매 편 할 일
1. 편집 시작 전에 그 편 이야기로 **후킹 후보 10개**를 만들어 사용자에게 보여 준다 — 후보마다 쓴 전략 이름을 붙인다(아래 형식).
2. 그중 **썸네일 자막(0-1) 하나를 추천**하고, 사용자가 고르면 그걸 영상 첫 장면 노란 자막 + 인스타 본문 첫 줄로 쓴다.
3. 고른 문구는 회차 기록 표에 적는다(같은 전략이 연달아 겹치지 않게).

### 필수 조건(원자료) — 우리 식으로
- 한 문장은 짧고 세게. 썸네일 자막은 **2줄, 한 줄 10자 안팎**(118px 글자가 화면에 들어가는 길이).
- 초등학생도 아는 쉬운 말. 「주제 + 대상 + 결과」가 첫 문장에 — 예: 요리(주제) + 아이/할머니(대상) + 한 그릇 뚝딱(결과).
- 숫자·감정·결과·궁금증 섞기(「5분」「재료 2개」「양파 하나로」 등 **실제 숫자만**).
- 저장·공유하고 싶게: 「이거 우리 집 얘기다」 싶은 공감, 바로 따라 할 수 있는 결과.
- 말하듯 자연스럽게. AI 말투·뻔한 표현 금지(「놀라운」「꿀팁 대방출」「인생 레시피」 같은 말 X).
- 1~2줄. 결과·감정·호기심의 균형.
- **우리만의 추가 규칙**: 사실과 다르게 지어내지 않는다(그날 실제 상황·실제 대사에서만). 정답은 영상 안에서 풀린다. 아이·가족 이야기가 중심이고 쿡매치는 해결 도구로 자연스럽게.

### 26가지 전략 — 우리에게 잘 맞는 것 / 조건부 / 안 쓰는 것
- **잘 맞음**: 1 결과 강조형 · 5 상식 파괴형 · 6 해결책 제시형 · 7 가능성 확장형 · 11 감정 공감형 · 13 경고형(가볍게) · 14 실험 결과형 · 15 흔한 실수형 · 17 디테일 분석형 · 18 현실 직시형 · 19 변화 스토리형 · 21 작은 행동 큰 결과형 · 22 빠른 이해형 · 23 반대 의견형 · 25 기능 활용형(쿡매치) · 26 쉬운 방법 제시형

## 1. 원본 받기

- 사용자가 폰 OneDrive 앱으로 `OneDrive/쿡매치_요리영상/요리명_YYYYMMDD/` 에 올린다 → PC `C:\Users\user\OneDrive\쿡매치_요리영상\요리명_YYYYMMDD\` 로 내려온다(폴더는 「항상 이 기기에 유지」).
- 파일 이름의 시각(`20261015_102150000_iOS.MOV`) 순서 = 찍은 순서. 사용자가 순서·용도를 말해 준다.
- `my-video/public/cooking/요리명_YYYYMMDD/` 로 복사해서 나눈다: `0_story/`(오늘의 이야기, 예: 하원길) · `1_cooking/`(요리, 식판 사진, 아이 먹는 영상) · `2_app/`(쿡매치 화면 녹화). 영상·사진·`work/` 는 git 제외(`.gitignore`).
- 대화창 첨부(`~/.claude/uploads/...`)로 오는 짧은 영상도 같은 폴더에 넣는다.

## 2. 작업본 만들기 (`work/`)

- 요리·아이·이야기 영상: `scale=1080:1920,fps=30`, H.264 (폰 4K HEVC·회전 메타 정리). 아이 영상·이야기 영상은 소리 유지(`-map 0:a:0`).
- 앱 화면 녹화(1206x2622, 60fps): 위 200px(상태바·녹화 빨간 점·시각) 잘라 1206x2422, 30fps. **홈캠 등 개인 알림 배너가 뜬 구간은 윗단 170px 만 흐림**(`overlay ... enable='between(t,a,b)'`). 프레임 하나씩 보고 배너 구간을 찾는다.
- 사진은 EXIF 회전 적용(`ImageOps.exif_transpose`)해서 `plate.jpg`.
- 내용 파악: 1fps 썸네일 시트 + Whisper(medium, `word_timestamps`) 로 대사·시각을 찾는다.

## 3. 릴스 구성 (순서 고정)

1. **오늘의 이야기** (~10s) — 왜 이 요리를 했는지. 원래 소리가 이야기와 다르면 끄고 자막으로. 예: 「하원길에 물어봤어요 / 오늘 저녁 뭐 먹고 싶어?」 → 「소시지!」(큰 노란 글씨) → 「쏘야엔 파프리카·당근도 필요한데 / 집에 있는 채소는 양파뿐…」.
2. **요리** (~25s) — 첫 장면에 제목(「5분 완성」 노란 칩 + 요리명). **자막은 레시피를 알려 주듯 단계별 정보**(분량은 앱 레시피 카드 그대로). 2~3.5배 빨리감기, 무음.
3. **식판 사진** (~3.5s) — 주인공 음식 칸을 가운데로 두고 천천히 줌(「아이 식판엔 소시지 듬뿍」).
4. **아이 먹는 모습** (~11s) — 행복해 보이는 장면 + 말하는 장면은 원음, 말은 큰 자막(아이 말은 노랑).
5. **쿡매치 화면** (~25s) — 이 레시피를 어떻게 찾았는지:
   - 레시피는 유튜브·네이버 상위 채널에서 검증된 것 → 그중 「인기순」 정렬
   - 「꼭 넣을 재료」에 주재료 입력 (냉장고에 재료를 담는 장면은 넣지 않는다 — 꼭 담아야만 되는 것처럼 보임)
   - 결과 → 레시피 카드 하단 줌: ① 「내 재료 11/11 (87%)」 매칭률 ② 「당근 → 양파」 같은 대체 재료 칩(노란 링 + 자막)
   - 상세 → 완료
6. **이 편 맞춤 CTA** — 그 편의 핵심 기능 릴스 슬로건 + 스토어 검색 + 프로필 링크(`CtaOutro`). 대체 재료가 핵심이면 2편 「없는 재료 대신, 있는 걸로 바꿔드려요」. 슬로건 목록은 `src/Reel1~8*.tsx` 의 `payoffLine`.
7. **전환** — `Intro line1="그 밖에도" line2="이런 기능이 있어요"` (ReelOverview 인트로 재사용).
8. **8개 기능 풀영상** — `OverviewSegments`.
9. **대표 슬로건 CTA** — `OverviewCta`(「있는 재료로 오늘 저녁 해결」 = 앱스토어 부제).

### 2편에서 더한 규칙
- **첫 훅은 의아함**: 첫 2~3초에 큰 노란 글씨로 「황태로도
미역국을 끓인다고?」처럼 궁금하게(사용자 요청). 그다음 이야기 자막.
- **이야기 순서가 「찾고 → 요리」면 앱 부분을 요리 앞에** 둔다(2편). 「요리 → 어떻게 찾았냐」면 뒤(1편).
- **단계 자막·본문 레시피는 사용자가 실제로 따라 한 레시피 카드 분량**으로(사용자가 캡처를 주면 그걸 기준). 앱 녹화에 보인 레시피와 다를 수 있다.
- **음악은 편마다 다르게**(사용자: 2편이 1편과 비슷하다). 1편 `bgm_vlog_bright.mp3`(기타 108BPM, `make_vlog_bgm.py`), 2편 `bgm_waltz_warm.mp3`(피아노 왈츠 3/4, `make_bgm_waltz.py`). 새 편은 다른 악기·박자·조로 새로 합성하고 여기 적는다.
- **대사 자막은 누가 한 말인지 정확히**(2편: 「황태로 끓이자」는 엄마가 아니라 할머니 — 「할머니, 무슨 미역국 먹을 수 있어..?」「황태로 부드럽게 끓이면 먹을 수 있으려나…」). 사용자 이야기를 그대로 옮긴다.
- 원음 대사(노래·대화)가 있는 장면은 음악을 0 으로(`TALK_WINDOWS`), 대사는 큰 자막(`Said`).

## 4. 화면·소리 규칙

- 1080x1920, 30fps. 요리·아이 영상은 9:16 꽉. 앱 녹화는 폰 비율(9:19.5)이라 높이에 맞추면 양옆 흰 여백(956px 폭) — 의도된 것.
